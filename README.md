# Pitwall

Local cockpit for supervising terminal-based AI coding agents.

Pitwall wraps around Claude Code, Codex, or any terminal-based agent and provides:
- Embedded terminal (PTY)
- Real-time file and git change tracking
- Event ledger with full session replay
- Race Engineer supervisor (LLM-powered, stub by default)
- Claims and evidence tracking
- Safety gates

## Status

This is an MVP. See the honesty table below.

### What works

| Feature | Status | Notes |
|---------|--------|-------|
| PTY Broker | **Implemented** | node-pty, tested with bash |
| Event Ledger | **Implemented** | SQLite append-only, persisted to `~/.pitwall/sessions/` |
| Repo Watcher | **Implemented** | chokidar file system monitoring |
| Git Monitor | **Implemented** | simple-git diff/status polling against HEAD |
| Command Detector | **Implemented** | Heuristic, supports `$`/`%`/`>`/`>` prompts |
| Test Detector | **Implemented** | jest, vitest, pytest, go test, cargo test — no false positives on generic errors |
| Claims Manager | **Implemented** | Detects driver claims, emits `claim.detected` events, persisted in ledger |
| Claim/Evidence Causality | **Implemented** | Temporal ordering: evidence must occur after claim. `evidence_captured` != `verified` |
| Gates | **Implemented** | Visual only — commit, migration, dependency, deploy, destructive_command |
| Secret Redactor | **Implemented** | Strips API keys, tokens, private keys before LLM |
| Auth/Security | **Implemented** | Server binds 127.0.0.1, per-process auth token, validated WS messages |
| Timeline | **Implemented** | Loads from API on connect, appends via WebSocket, survives refresh |
| Start Session UI | **Implemented** | Bash/Claude/Codex presets, dangerous mode requires confirmation |

### What is stubbed

| Feature | Status | Notes |
|---------|--------|-------|
| Race Engineer LLM | **Stub** | `StubLLMAdapter` generates context-aware responses from mission state. Replace with real API adapter for full capability. |
| Shadow Lanes | **Stub** | Lane observations are generated by stub LLM. UI has manual "Refresh" button. Lanes work end-to-end but responses are synthetic. |

### What is not implemented

| Feature | Notes |
|---------|-------|
| Real fleet orchestration | Non-goal for MVP — shadow lanes are derived observers |
| GitHub/Linear/Slack integration | Planned for later |
| Production deploy | Local-only by design |
| No-cloud LLM mode | Planned |
| Gate enforcement | Gates are visual indicators, not blockers |
| Full replay UI | Timeline shows events; no video/scrollback replay yet |

## Quick Start

```bash
# Install dependencies (requires C++ build tools for node-pty)
npm install

# Run checks
npm run typecheck
npm run lint
npm run build
npm test

# Start dev mode (Electron + Vite)
npm run dev
```

### Requirements

- Node.js 18+
- C++ build tools (for node-pty native compilation)
  - Linux: `sudo apt-get install build-essential python3`
  - macOS: `xcode-select --install`

## Architecture

```
Frontend (React + xterm.js)
  |
  v
Local Server (Express + WebSocket, port 4850, bound to 127.0.0.1)
  |
  v
Core Modules:
  PTY Broker -> Event Ledger (SQLite)
  Repo Watcher -> Event Ledger
  Git Monitor -> Event Ledger
  Command Detector, Test Detector -> Claims Manager -> Event Ledger
  Race Engineer (LLM) <- Mission Packet (built from event state)
  Shadow Lanes <- Event Ledger
```

## API

All `/sessions/*` routes require `Authorization: Bearer <token>`.
Token is generated per-process and available via `GET /auth/token`.

| Method | Path | Description |
|--------|------|-------------|
| POST | /sessions | Create session |
| POST | /sessions/:id/input | Send terminal input |
| POST | /sessions/:id/radio/ask | Ask Race Engineer |
| POST | /sessions/:id/radio/send-to-driver | Send instruction to driver |
| GET | /sessions/:id/state | Full session state |
| GET | /sessions/:id/timeline | All events |
| POST | /sessions/:id/interrupt | Send Ctrl+C |
| POST | /sessions/:id/snapshot | Save snapshot |
| POST | /sessions/:id/lanes | Refresh shadow lanes |
| DELETE | /sessions/:id | Stop session |

WebSocket: `ws://127.0.0.1:4850/ws?sessionId=...&token=...`
